# X Pulse · 需求机会雷达

Manifest V3 浏览器扩展，原生 JavaScript、零第三方运行依赖。浏览 X 时继续显示粉丝数、账号详情和独立的账号收藏；手动扫描当前页面已观察到的帖子与评论，从真实讨论中发现值得关注的需求，以及可能可以做或卖的产品与服务。

## 安装

1. 运行 `node build.cjs`，或使用仓库中的 `dist/`。
2. 在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，指向 `dist/`。升级后在扩展管理页重新加载，并刷新已打开的 X 页面。

## 使用

1. 在 Popup 的“AI 设置”填写 OpenAI 兼容服务的 Base URL、API Key 和模型，点击“测试连接并授权域名”。默认超时 30 秒。测试失败时展示接口状态、服务商错误；空响应展示可用的结束原因和 token 使用情况。扫描**不需要产品配置**。
2. 打开 X 页面，等待帖子或评论加载。在右下角悬浮的需求机会雷达中点击“扫描当前页面”。面板可拖动位置、关闭，并通过“需求雷达”按钮重新打开。每次最多分析 100 条已观察到的讨论，每个 AI 请求最多 10 条；滚动加载更多后可点击“分析下一批”。扩展不会主动请求 X API。
3. AI 结合上下文判断具体需求，并参考已有需求主题，把语义相同的讨论归为一张“需求机会”卡。卡片显示出现次数、典型原话、痛点、目标用户、趋势、付费信号、当前方案、竞争线索、机会评分和可能方向。
4. “发现的需求”是待审阅区。点击“加入机会池”后，该机会才会出现在机会池；可以收藏、备注、加标签或移出。单条评论不会自动进入机会池。

粉丝徽标、账号悬停卡片、账号收藏和 CSV/JSON 导出保持独立。旧版产品配置与按评论保存的商机数据不会删除，但不再参与新扫描，也不会混入需求机会池。

## 判断和数据边界

- 轻量本地规则只排除纯闲聊、明显广告和过短内容；是否存在需求由 AI 结合帖子及可用父帖上下文判断，不按预设产品或关键词筛选。
- 原帖和评论都会独立参与需求分析。没有缓存到 X 响应文本时，使用当前页面已显示的帖子正文兜底；不会为此主动请求 X API。
- 需求原话、付费信号、现有方案和竞争线索必须能在已观察讨论中找到逐字证据。没有明确付费表达时付费分为 0；未在讨论中发现竞争线索时显示“讨论样本不足”。这里的竞争判断不是市场调查。
- 出现次数是已扫描的不同帖子数，不代表全站频率。趋势仅在有足够日期跨度的样本时计算，并明确标为“已扫描样本”；否则显示“样本不足”。机会评分依据需求强度、样本频率、痛点、付费信号和讨论中的竞争线索在本地计算，不保证商业成功。
- AI 仅收到手动扫描选中的帖子文本、可用父帖文本、发布时间以及已有需求主题摘要。Cookie、X Token、请求头和完整 X 响应不会发送。API Key 只保存在扩展本地存储中，由后台用于请求你配置的 AI 服务。
- 分析缓存、需求证据、聚类卡、机会池、备注和标签只保存在本机。改动模型、接口或讨论上下文后会重新分析；失败批次不会自动重试，避免重复产生付费请求。
- 可选主机权限仅在测试 AI 连接时针对填写的服务域名申请；不增加 X 请求权限或 `<all_urls>` 必需权限。

## 开发与测试

```bash
node build.cjs
node --test tests/*.test.cjs
```

`src/page/bridge.js` 只观察页面已有的 X 响应；`src/shared/transport.js` 提取用户与帖子；`src/content/opportunity-ui.js` 管理扫描入口与需求标记；`src/shared/opportunity.js` 校验证据并汇总主题；`src/shared/ai-client.js` 调用 AI；`src/shared/opportunity-store.js` 管理本地发现和机会池；`src/background.js` 串行化写入并执行跨域 AI 请求。`dist/` 是构建产物。

真实 X 页面结构和 AI 服务输出可能变化。自动测试无法替代在已登录、已加载讨论的 X 页面和你配置的 AI 服务上做端到端验收。
