## 3. 数据模型差异（关键）

### 3.1 UserRecord：字段命名与 ID 丢失

| 方案字段 | 当前字段 | 说明 |
| --- | --- | --- |
| `followers` | `count` | 命名不一致，需统一 |
| `observedAt` | `at` | 命名不一致，需统一 |
| `id` | （丢失） | **真 bug**：`core.extractUsers()` 提取了 `id`，但 `store.sanitize()` 通过 `validateSample()` 重建对象时把 `id` 丢掉 |

当前链路（`src/shared/`）：

```
core.extractUsers(payload)  →  { handle, count, id, name, avatar, following, posts, createdAt, followsYou, youFollow }
        ↓
store.sanitize(raw)  →  validateSample({...raw, at})  →  { handle, count, at, name, avatar }   ← id 在此丢失
        ↓                     + following/posts/createdAt/followsYou/youFollow
        →  最终 UserRecord 无 id
```

修复方式二选一（需拍板，见 §6 决策点 D1）：

- **A（推荐）**：`validateSample` 与 `sanitize` 都显式保留 `id`（并统一字段名），一次性修好数据链路。
- **B**：不改命名，仅在 `sanitize` 里把 `id` 补回来（最小改动，但字段名仍与方案不一致）。

### 3.2 PostRecord：全新

无现有对应物。`tweet.js` 需要：

- `extractPosts(payload)`：从 GraphQL 响应里遍历提取推文节点。
- `normalizePost(raw)`：规范化到 `PostRecord`。
- `getPostIdFromDOM(article)`：从推文 DOM 稳定地取 Post ID（这是 XP-02 最难点，需真实页面样本确定选择器/属性）。

### 3.3 设置模型

| 现状 | 方案 |
| --- | --- |
| `src/shared/settings.js`：扁平 `{enabled, layout, format, tierColors, hoverCard, showRelation, debug}` | 新增 `schemaVersion: 2` + 嵌套 `account/post/filters/favorites`，同时保留旧扁平字段 |
| 无迁移逻辑 | `config.js` 负责默认值合并、类型校验、旧→新迁移、范围限制、未知字段过滤 |

> 存储键保持 `xp_inline_settings`（兼容），新增 `xp_v2_favorites`、`xp_v2_schema_version`。
